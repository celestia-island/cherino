# الواجهات الخلفية

يعامل Cherino عزل الحاويات بوصفه مسألة «سياسة فوق آلية»: المنصة
تصف *ما* هو مسموح (عبر ملفات الأمان)، وتترجم كل واجهة خلفية ذلك
إلى آليتها الأصلية (إعدادات مضيف Docker أو خطّافات مواصفة OCI).
جميع الواجهات الخلفية تطبّق سمة `ContainerOps` نفسها.

| الواجهة الخلفية | النوع | المنصة | الآلية | المستوى |
|---------|------|----------|-----------|------|
| **Docker** | API | الجميع | Bollard → Docker Engine HTTP API | أساسي |
| **Youki** | أصلي | Linux | libcontainer → حاويات OCI دون امتيازات الجذر | احتياطي |
| **WSLc** | CLI | Windows | استدعاء صدفي لـ `wslc.exe` / `container.exe` | احتياطي |
| **Apple Container** | CLI | macOS 26+ | أداة `container` السطرية (آلة افتراضية لكل حاوية) | احتياطي |

## Docker (أساسي)

واجهة Docker الخلفية هي الافتراضية والمسار الأكثر اختبارًا في الميدان.
يتصل `ContainerManager` بخادم Docker المحلي عبر Bollard ويطبّق
سطح `ContainerOps` الكامل، بما في ذلك exec ونسخ الملفات واللقطات
والوحدات التخزينية وإدارة الصور. وهو متاح على كل منصة خلف ميزة
`docker` الافتراضية.

```rust
use cherino::ContainerManager;

let mgr = ContainerManager::new()?; // local daemon
// or, against a specific socket:
let mgr = ContainerManager::new_with_socket("/var/run/docker.sock")?;
```

## Youki / libcontainer (احتياطي، Linux)

توفر حِزمة `cherino-runtime` النوع `YoukiManager`، وهو واجهة خلفية
أصلية لـ OCI مبنية على libcontainer. وهي **دون امتيازات الجذر ودون
خادم خلفي**: تعمل الحاويات بصلاحيات المستخدم المُستدعي دون أي خدمة
خلفية، ما يجعلها الاحتياطي للمضيفين الذين لا يتوفر أو لا يُسمح لديهم
بخادم Docker.

يبني `cherino-runtime` واجهته الخلفية الحقيقية تلقائيًا على
`cfg(target_os = "linux")`. وعلى كل منصة أخرى يترجم بديلًا شكليًّا
تعيد استدعاءاته أخطاء «متاح فقط على Linux»، بحيث يمكن للشيفرة
متعددة المنصات الاعتماد عليه دون شروط.

**Youki من المستوى الاحتياطي**: يُصان بوصفه بديلًا دون امتيازات
الجذر، لا مشغّل التنسيق الأساسي. فضّل واجهة Docker الخلفية كلما
توفر خادم.

## الواجهات الخلفية السطرية (احتياطي، Windows / macOS)

خلف ميزة `cli-backend` الاختيارية، يشحن cherino محوّلات سطرية
لأوقات تشغيل الحاويات التي لا تكشف واجهة برمجية محلية مستقرة:

- **WSLc** على Windows — يستدعي صدفيًا `wslc.exe` / `container.exe`.
- **Apple Container** على macOS 26+ — يقود أداة `container` السطرية،
  التي تشغّل آلة افتراضية خفيفة لكل حاوية.

ميزة `cli-backend` معطّلة افتراضيًا؛ فعّلها صراحةً على مضيفي
Windows/macOS:

```toml
[dependencies]
cherino = { version = "0.1", features = ["cli-backend"] }
```

## معمارية وقت تشغيل ذات طبقتين

تستخدم منصة celestia وقتَي تشغيل حاويات مختلفَين في طبقتين مختلفتين:

| الطبقة | وقت التشغيل | المستخدمون |
|-------|---------|---------|
| **الخارجية** (التنسيق) | Docker/Podman | فحص صحة TUI، خادم scepter، مدير الخوادم |
| **الداخلية** (عزل cosmos) | Youki/libcontainer | مدير Snowflake، حالة وكيل Neikos |

تدير الطبقة الخارجية حاويات البنية التحتية (scepter وpostgres) عبر
واجهة Docker/Podman البرمجية؛ إذ تحتاج هذه إلى ميزات التنسيق الكاملة —
الشبكات، والوحدات التخزينية الدائمة، وفحوص الصحة، وتركيب الحاويات
المتعددة. أما الطبقة الداخلية (Cosmos) فتعمل *داخل* حاوية scepter
وتستخدم Youki لإنشاء حاويات معزولة خفيفة سريعة الإقلاع لتنفيذ
الوكلاء، لكل منها ملف seccomp خاص بها وحدودها للموارد.

## رايات الميزات

`cherino`:

- `docker` *(افتراضية)* — واجهة `ContainerManager` الخلفية المبنية على Bollard.
- `cli-backend` — محوّلات WSLc / Apple Container السطرية. معطّلة افتراضيًا.
- `docker-tests` — اختبارات تكامل تتطلب خادم Docker حيًّا
  (معطّلة افتراضيًا؛ تستلزم `docker`).
